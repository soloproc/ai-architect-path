附录：全站术语表——遇到不懂的词，先查这里

导师的话：这套教程横跨服务端、数据系统、分布式、SRE、AI Infra 与 Agent 工程六大领域，术语密度不低。新手最常见的放弃原因不是"内容难"，而是"一句话里三个生词，查不过来"。这一页就是为此准备的：阅读中任何卡壳的术语，先回到这里查人话解释，再顺着"首次出现"的链接回到正文看完整上下文。

本页收录 73 条术语、6 个分组，覆盖全站 28 个子页与保留页中所有"不查就读不下去"的硬核词汇；每条解释都控制在 40 字以内，类比优先、不照抄定义。

怎么用这本词典

  1. 卡壳即查：读到不懂的词，用浏览器页内搜索（Ctrl/Cmd + F）在本页定位，看一句话解释就够了，不必立刻钻细节。
  2. 回链补上下文：解释右侧的"首次出现"链接指向该术语第一次被正式讲解的子页与章节，点回去读那一段，理解才算闭环。
  3. 不要顺序背：这不是单词书。术语是按学习路径分组的，跟着正文学到哪组、查哪组即可。
  4. 口径说明："首次出现"指该术语在学习路径顺序下首次被正式讲解的位置；个别在早期一笔带过、后期才展开的词，标注的是首次详解处。

一次完整的查词示范

假设你正在读卷04-1，看到这句话卡住了：

"熔断防的是'持续调用一个已确定挂掉的下游'，它和限流、降级不是一回事。"

三步走完一次查词闭环：

  1. 回到本页，页内搜索"熔断"，在第四组表格里找到它——一句话解释是"下游确定挂了就先跳闸别打了，隔会儿再试探一次"。
  2. 顺手扫一眼上下两行，你会发现"限流"和"降级"就在旁边——三个词本来就是一组，一起看比单独看省一半力气（本页开头的"高频易混"表已经替你对比好了）。
  3. 点解释右侧的链接回到 卷04-1 §2.3，读那一节的完整推导和 50 行迷你熔断器代码。

到这一步，"熔断"对你就不再是一个"听说过的词"，而是一个"知道为什么存在、什么时候用"的工具。词典负责第 1 步，第 2、3 步才是学习。

易混组合 一句话区分
穿透 / 击穿 / 雪崩 穿透打"不存在的"，击穿打"一个爆品"，雪崩是"一大批同时到期"

一、服务端基础（卷01）

一切架构的起点：一次请求怎么进来、一台机器怎么同时服务很多人、数据库连接为什么是个池。这组词是全站使用频率最高的"普通话"——后面每一卷的正文都默认你已经认识它们。

什么时候会密集遇到：卷01-1（HTTP/TCP/REST/并发模型）、卷01-2（连接池/N+1）。学完卷01，本组 9 个词应该全部能"见词知意"。

术语 一句话 首次出现
HTTP（HyperText Transfer Protocol） 浏览器与服务端之间的"标准点菜单"，点什么、上没上错都有格式 卷01-1 §1.1
TCP（Transmission Control Protocol） 传数据前先握手"接通电话"，挂断也要双方确认 卷01-1 §1.5
REST（Representational State Transfer） URL 说"什么东西"，方法说"干什么"：GET 看、POST 办 卷01-1 §2
进程（Process） 一人一间独立办公室，互看不见内存，安全但开销大 卷01-1 §3.2
线程（Thread） 同一办公室多张工位，共享文件柜，快但要防抢 卷01-1 §3.2
协程（Coroutine） 一个人同时看多口锅，哪锅开了先顾哪锅 卷01-1 §3.2
IO 多路复用（IO Multiplexing） 一个服务员盯一百张桌，谁举手就服务谁 卷01-1 §3.3
连接池（Connection Pool） 数据库连接像共享雨伞：借了要还，别每次新买 卷01-2 §4.2
N+1 问题（N+1 Query Problem） 查 1 次列表再循环查 N 次详情，像跑 N+1 趟超市 卷01-2 §4.3

二、架构演进（卷02）

RetailHub 的四次"手术"用到的一整套词汇。记住全站主线：每次演进都是症状逼出来的，不是技术痒。这组词几乎每个大厂面试都会问。

什么时候会密集遇到：卷02-1（缓存三兄弟、读写分离、分库分表）、卷02-2（MQ、负载均衡、一致性哈希）、卷02-3（大促实战里全部串一遍）。

术语 一句话 首次出现
缓存穿透（Cache Penetration） 专查根本不存在的东西，缓存形同虚设，全砸数据库 卷02-1 §2.3
缓存击穿（Cache Breakdown） 一个爆品缓存恰好过期，万人同时冲去数据库重算 卷02-1 §2.3
缓存雪崩（Cache Avalanche） 大批缓存同一时刻集体到期，像整栋楼的伞同时被收走 卷02-1 §2.3
读写分离（Read-Write Splitting） 主库管写、从库管读，像后厨与前厅分工 卷02-1 §3.1
分库分表（Sharding） 一本账记不下就分柜，按用户 ID 取模路由到不同库 卷02-1 §3.3
消息队列（Message Queue, MQ） 下单先塞张"取号单"就走，后厨按自己节奏做 卷02-2 §4.1
负载均衡（Load Balancing） 门口的领位员，把客人均匀领到空闲窗口 卷02-2 §5.3
一致性哈希（Consistent Hashing） 加一台机器只让约 1/N 的客人换座，而不是全体重排 卷02-2 §5.3
服务化（Service Splitting） 团队互相挡路时，把大应用按业务能力拆成小分队 卷02-2 §5.2

三、数据系统（卷03 + 卷04-2）

DDIA 的核心词汇。这一组回答两个问题：数据在单台机器上怎么存得又快又稳，跨机器之后凭什么还能信。

什么时候会密集遇到：卷03-1（存储引擎三件套 LSM/B-Tree/WAL）、卷03-2（MVCC/隔离级别/CAP）、卷04-2（BASE 与四种分布式事务方案、Raft）。布隆过滤器例外——它在卷02-1 治缓存穿透时就提前登场了。

术语 一句话 首次出现
LSM-Tree（Log-Structured Merge-Tree） 先记流水账、攒够一批再统一誊正，写得飞快 卷03-1 §3
B-Tree（Balanced Tree） 像字典的部首索引：原地翻页改字，读快写随机 卷03-1 §3
WAL（Write-Ahead Log） 先记小账再改大账，断电后照小账重放就能恢复 卷03-1 §3
布隆过滤器（Bloom Filter） 门口的"绝对不卖清单"：它说没有，就一定没有 卷02-1 §2.3
MVCC（Multi-Version Concurrency Control） 每个读者发一份"当时快照"，读写互不排队 卷03-2 §7
隔离级别（Isolation Level） 事务之间的"隔音等级"：从听得到邻桌到完全包间 卷03-2 §7
CAP（Consistency, Availability, Partition tolerance） 断网时只能二选一：宁可拒答保正确，还是带病也营业 卷03-2 §9
BASE（Basically Available, Soft state, Eventually consistent） 允许暂时错，但保证会修好，且修好的过程可追溯 卷04-2 §3
2PC（Two-Phase Commit） 班长先问"都准备好了吗"，齐答好了才喊"执行" 卷04-2 §3.1
TCC（Try-Confirm-Cancel） 先占座（Try），成了转正（Confirm），黄了释放（Cancel） 卷04-2 §3.2
Saga 长旅程分段买票，中途失败就按反序逐段退掉 卷04-2 §3.3
Raft 分布式世界的"选举 + 少数服从多数"宪法 卷04-2 §3.6
共识（Consensus） 一群会掉线的机器，对同一件事达成一致意见的本领 卷04-2 §3.6

四、平台与可靠性（卷04-1/3 + 卷08）

从"能跑"到"敢承诺"。前半组是流量治理的安全气囊，后半组是 SRE 把"稳定性"变成可谈判数字的语言体系。

什么时候会密集遇到：卷04-1（熔断/限流/降级/单元化）、卷04-3（平台工程/IDP/两地三中心）、卷08 三子页（SLI 全家桶、燃烧率、oncall、混沌工程）。这组是进入篇09「评测门禁」之前的最后一块传统工程地基。

术语 一句话 首次出现
熔断（Circuit Breaker） 下游确定挂了就先跳闸别打了，隔会儿再试探一次 卷04-1 §2.3
限流（Rate Limiting） 门口发号：超出接待能力的，一律礼貌排队或劝退 卷04-1 §2.4
降级（Degradation） 高峰期砍掉雕花装饰，保住主菜能上桌 卷04-1 §2.5
单元化（Unit Architecture） 把全国用户分成若干"自治小区"，炸一个不伤全城 卷04-1 §2.7
平台工程（Platform Engineering） 把好用的基础设施做成产品，让所有服务默认继承 卷04-3 §7
IDP（Internal Developer Platform） 公司内部"自助餐厅"：部署、监控、发布不用求人 卷04-3 §7.2
两地三中心 同城双中心抗机房级故障，异地一中心抗城市级灾难 卷04-3 §7.4
SLI（Service Level Indicator） 拿尺子量出来的数字，比如"请求成功率 99.95%" 卷08-1 §2.1
SLO（Service Level Objective） 对内立的军令状：这把尺子必须量到多少 卷08-1 §2.1
SLA（Service Level Agreement） 对客户签的合同：达不到就赔钱的那种 SLO 卷08-1 §2.1
错误预算（Error Budget） 一年允许坏的几十分钟是"存款"，花完就冻结新功能 卷08-1 §2.5
燃烧率（Burn Rate） 错误预算的"花钱速度"：烧太快会提前破产，必须报警 卷08-2 §3.5
RED（Rate, Errors, Duration） 服务监控三问：多忙？错多少？多慢？ 卷08-2 §3.2
USE（Utilization, Saturation, Errors） 资源体检三看：用多满？排多长队？报错没？ 卷08-2 §3.2
Oncall（值班） 可靠性的最后一道人肉防线：手机不能静音的那个人 卷08-2 §4.1
Postmortem（复盘） 事故后只问"系统怎么骗了我们"，不追"谁的锅" 卷08-2 §4.4
混沌工程（Chaos Engineering） 主动在自家放火演习，验证消防通道真的好使 卷08-3 §5.4

五、AI 基建与 Agent（篇00-10 + 卷06/07）

本教程区别于传统架构课的核心词汇区。前半组管"模型怎么跑得又快又便宜"，后半组管"Agent 怎么被管住"——后者是全站后半程的通用语。

什么时候会密集遇到：篇01（Token/KV Cache/ReAct/Workflow）、卷06 两子页（推理性能与成本词汇）、篇05（Harness/Run）、篇07（沙箱/MCP/Skill）、篇08-09（记忆、评测门禁）、卷07（FDE）。如果这组词你有一半陌生，说明该从篇01 开始而不是从中间跳读。

术语 一句话 首次出现
Token 模型的"最小文字积木"，也是计费表上跳动的数字 篇01 §1.1
KV Cache（Key-Value Cache） 模型的"草稿纸"：前面算过的注意力留着不重算 篇01 §1.3
ReAct（Reasoning + Acting） 让模型"想一步、做一步、看一眼"滚动前进的循环 篇01 §2.2
Workflow（工作流范式） 把任务流程画成固定施工图，模型只砌墙不管设计 篇01 §2.3
RAG（Retrieval-Augmented Generation） 开卷考试：先查资料放桌上，再让模型作答 篇00-2 §5.3
Roofline（屋顶线模型） 一张图判断瓶颈：是算不动（算力），还是搬不快（带宽） 卷06-1 §1.3
量化（Quantization） 把模型权重从精装书压成口袋书：省显存，略掉精度 卷06-1 §2.2
PagedAttention 给 KV Cache 分页管理显存，像操作系统管内存一样不浪费 卷06-1 §3.2
TTFT（Time To First Token） 点完菜到第一口上桌的时间，决定"卡不卡"的体感 卷06-1 §3.3
TPOT（Time Per Output Token） 之后每吐一个字的节奏，决定"顺不顺"的体感 卷06-1 §3.3
HNSW（Hierarchical Navigable Small World） 向量世界的"多级地图"：先找省、再找市、再找街 卷06-2 §5.2
Harness 包住模型的"脚手架 + 护栏"：工具、校验、重试、权限都在这层 篇05-1 §2.1
Run 一次任务的完整"航班号"：状态、步骤、事件、断点全挂它名下 篇05-1 §3.1
沙箱（Sandbox） 模型写的代码关进笼子跑：默认拒绝，越界即审计 篇05-2 §5.5
MCP（Model Context Protocol） 工具世界的"USB 接口标准"，插上就能被模型使用 篇07-2 §5.1
Skill 把一次成功做法固化成的"菜谱文件"：触发条件、步骤、验收 篇07-2 §4.2
记忆三分类（工作 / 情景 / 语义记忆） 工作记忆是当下桌面、情景记忆只存指针、语义记忆才进档案库 篇08-1 §1.1
评测门禁（Regression Gate） Agent 上线前的"安检门"：分数掉线就不放行 篇09 §9.5
FDE（Forward Deployed Engineer） 进驻客户现场、对"问题解决"而非"部署完成"负责的工程师 卷07 §1.1

六、方法论与其他（卷01-05 贯穿）

数量最少、复利最高的一组。它们是架构师"把判断变成资产"的基本功，也是从第一天就反复出现的暗线词——幂等在卷01-1 就埋下，一路用到篇07 的工具设计三原则。

什么时候会密集遇到：卷05-1 是主战场（质量属性/4+1/ATAM/ADR）；幂等与最终一致则分别在卷01-1、卷02-2 首次登场，之后全站无处不在。

术语 一句话 首次出现
幂等（Idempotency） 同一操作重复十次效果和一次一样：网络重试的保命符 卷01-1 §1.3
最终一致（Eventual Consistency） 报表晚 3 秒没关系，只要保证最后一定对得上 卷02-2 §4.3
质量属性（Quality Attribute） "快"不是需求，"P99 ≤ 300ms @ 500 QPS"才是 卷05-1 §3.1
4+1 视图（4+1 View Model） 一栋楼要出五套图纸：逻辑、开发、进程、物理，加场景串起来 卷05-1 §4.1
ATAM（Architecture Tradeoff Analysis Method） 架构的"公开听证会"：把权衡摆上桌面逐个评 卷05-1 §6.2
ADR（Architecture Decision Record） 给每个重大决定留一页"当时为什么这么选"的档案 卷05-1 §7.2

给复习者的自测玩法

学完全路径后，这本词典可以当抽认卡用：

  1. 遮住"一句话"列：只看术语，逼自己说出人话解释，说完对照——能说到 80% 就算毕业。
  2. 遮住"首次出现"列：看术语回忆它属于哪一卷、是因为什么症状被引入的。答不上来的，就是需要回读的章节。
  3. 跨组连线：随便挑两个不同组的词（比如"幂等"和"评测门禁"），说出它们之间的关系。能在任意两个词之间搭上桥的，是真懂了；搭不上的，说明还是背了地图没走过路。

收尾：术语是地图，不是目的地

查到词、读懂一句话，只完成了 10%。真正的理解发生在你点回正文、看到这个词是在什么症状下被引入、付出了什么代价的时候。所以这本词典刻意只给"人话版"——精确定义、推导过程和代码骨架，永远在正文里。

如果某个词在这里查不到，先去该卷的「常见误区」和「参考与脚注」看看；仍然查不到，说明它超出本教程范围，带着你在正文里攒下的判断力去查原始资料即可——那时你已经不需要词典了。
