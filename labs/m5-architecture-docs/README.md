# M5 · 架构文档包实战（对应卷05《架构师方法论 / 软考备考与架构文档包实战》）

> 本里程碑**没有代码，也不需要运行**——卷05 的实战产物是文档：
> 把 RetailHub 前四卷"脑子里做的决策"落成一份**可参评的架构文档包**。
> 本目录提供全套可填模板，按步骤填完即完成卷05 实战。

## 前置环境

只需要一个文本编辑器（支持 Markdown + Mermaid 预览更佳，如 VS Code +
Markdown Preview Mermaid Support 插件）。无需 Python、无需安装任何依赖。

## 四份交付物（对应卷05-2 §10.2 递进任务）

建议按顺序推进：**视图是骨架，场景是承诺，ADR 是历史，评审是验收**。

| 步骤 | 交付物 | 模板位置 | 验收标准（摘要） |
|---|---|---|---|
| 1 | 4+1 视图图集（5 张 mermaid 图） | `docs/views/views-template.md` | 5 张图可渲染；场景视图能串联其余四视图；任一组件在逻辑/物理/开发视图中都有对应物 |
| 2 | 6 个质量属性场景（六要素格式） | `docs/quality-scenarios.md` | 每条六要素完整；响应度量全部含数字与口径（无"较高""尽量"）；至少 1 条有验证手段 |
| 3 | 3 份 ADR（真实发生过的决策） | `docs/adr/0000-adr-template.md` | 每份含背景/决策/被否决方案及理由/正负后果；状态字段完整；一页纸以内 |
| 4 | 模拟架构评审纪要 | `docs/reviews/review-minutes-template.md` | 每条质询有结论（风险/非风险/敏感点/权衡点）；每个风险有行动项、责任人、期限 |

## 模板目录结构（也是卷05-1 §7.4 推荐的目标结构）

```
m5-architecture-docs/
└── docs/
    ├── README.md                        # 导览索引模板（文档包唯一入口）
    ├── views/
    │   └── views-template.md            # 4+1 视图 mermaid 骨架（已按 RetailHub 卷04 末态预填）
    ├── quality-scenarios.md             # 六要素质量属性场景模板（含 1 条填好的示例）
    ├── adr/
    │   └── 0000-adr-template.md         # Nygard 标准 ADR 模板（含填写纪律）
    └── reviews/
        └── review-minutes-template.md   # 架构评审纪要模板（含结论分类与行动项表）
```

## 使用步骤

1. 把 `docs/` 复制到你自己的项目仓库根目录（文档与代码同仓同评审）。
2. 按上表步骤 1→4 依次把模板里的 `【填写：…】` 替换为你的真实内容。
3. 每份文档填上 owner 与"最近验证日期"（没有验证日期的文档读者不敢信）。
4. 对照卷05-2 §10.8 总验收标准逐条打勾。

## AI Coding 实操提示（卷05-2 §10.7）

AI 是文档的天然第一稿作者，但 **ADR 的"背景与被否决方案"必须由你口述给它**——
AI 不知道你当年为什么做那些决策，否则它会编造听起来合理的历史。
可复制的提示词模板与人工评审清单见卷05-2 §10.7。

## 常见误区（FAQ 形式）

- **Q：质量属性场景写成"高可用、高性能"行不行？**
  A：不行。没有响应度量（数字 + 口径）的场景无法设计、无法测试、无法评审，等于许愿。
- **Q：ADR 只写结论"决定采用 Kafka"可以吗？**
  A：没有价值。有价值的是"为什么否决 RabbitMQ 和 Pulsar"——考古的人要的是排除法的过程。
- **Q：被否决/被取代的旧 ADR 能删掉吗？**
  A：不能。"不可修改，只可取代"：Rejected 的提案是未来团队的排雷图；
  Superseded 的旧档只读保留，新 ADR 写明"什么约束变了"。
- **Q：画一张大架构图代替 4+1 视图？**
  A：一张图同时表达模块、部署、流程的结果是谁都看不懂。视图分离是给不同干系人各自的地图。
