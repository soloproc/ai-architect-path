# ADR 0001：GMV 统计不计入 refunded 订单

- 状态：已接受（卷01 实战，2025-06）
- 背景：`/stats/gmv` 需要定义 GMV 口径。订单有两种状态：`paid`、`refunded`。
- 决策：GMV 只统计 `status != 'refunded'` 的订单；`order_count` 同口径；客单价 = GMV / 该口径订单数。
- 理由：GMV 用于衡量"真实成交"，退款订单的钱最终退回用户，计入会高估经营成果；
  同时口径必须在 API 层固化，不能交给每个调用方自己过滤——口径不一致是数据平台最常见的"数据打架"根源。
- 代价与留门：退款金额本身也有经营价值（退款率分析），后续应新增独立指标（如 `refund_amount`）而非改变本口径；
  若未来引入"部分退款"，需重开本 ADR 评审口径。
