实操指南：手把手跑起来

实操这本教程有三种方式，可以混着用：

  • 在线运行，零安装看逻辑：章节实战区里的「▶ 在线运行」面板，代码直接在浏览器里跑（Pyodide，无需装 Python），适合快速看懂核心逻辑与验收口径；很多章节页还内嵌了可点击的交互 Demo（装配管线、熔断器状态机、Token 预算滑块……），打开网页直接玩。
  • ☁️ 云端虚拟机，真实环境跑完整服务：点章节里的「云端虚拟机」链接（GitHub Codespaces，账号一键开机），自动装好全部依赖的真实 Linux 环境——能跑 FastAPI 服务、开端口、发 curl，适合想做完整验收但不想折腾本机环境的同学。
  • 源码包，下载到本地跑：贯穿项目 RetailHub 的 9 个里程碑源码，解压后一条命令跑通，离线可用、完全掌控，本页教你怎么从零装环境、跑通第一个里程碑。

建议姿势：读章节时用「在线运行」建立直觉；想跑完整服务（含 FastAPI 端口、压测脚本）就开云端虚拟机；读到「本卷实战 / 本篇实战」要长期折腾时，下载源码包到本地，亲手跑通验收清单。

1. 环境准备（只做一次，macOS 为主）

源码全部是 Python 写的，唯一硬性要求是 Python ≥ 3.10。不需要装 Redis / MySQL / GPU——缓存用 fakeredis 模拟、数据库用 SQLite、推理服务是本地 mock。

1.1 检查 python3

打开「终端」（Terminal），输入：

python3 --version
  • 预期输出：Python 3.10.x 或更高（如 Python 3.12.4）✅ 直接跳到 1.3。
  • 如果提示 command not found，或版本低于 3.10，继续 1.2。

1.2 安装 python3（没有的话）

macOS 方式 A：安装苹果命令行工具（自带 python3）：

xcode-select --install

会弹出一个系统安装窗口，点「安装」等它装完（约几分钟），然后回到终端重新执行 python3 --version 确认。

macOS 方式 B：去 python.org 下载 macOS 安装包，双击一路「继续」，装完重新打开终端确认版本。

Windows 简要说明：去 python.org 下载 Windows 安装包，安装时务必勾选 "Add python.exe to PATH"；验证用 python --version（Windows 上通常没有 python3 这个命令，后面所有 python3 换成 python）。运行 shell 脚本（run.sh / bootstrap.sh）推荐用安装 Git for Windows 自带的 Git Bash；也可以在 PowerShell 里手动逐条执行等价命令（见 1.3 的括号注释）。

1.3 一键建环境

先下载全量源码包（见第 2 节）并解压，然后在终端进入解压出来的目录：

cd retailhub-source        # 你解压出来的目录名；里面是 m1-monolith、m2-cache-mq 等 9 个目录
bash bootstrap.sh

预期看到四步输出，每步一个 ✅：

== 1/4 检测 python3 ==
   python3 版本 3.12 ✅
== 2/4 创建虚拟环境 .venv ==
   已创建 .venv ✅
== 3/4 安装依赖（requirements-all.txt）==
   依赖安装完成 ✅
== 4/4 自检 ==
   核心依赖导入正常 ✅
🎉 环境就绪。下一步：source .venv/bin/activate …

bootstrap.sh 帮你做的三件事，等价于手工执行（Windows / 想理解原理的读者看这里）：

python3 -m venv .venv            # 建一个独立虚拟环境，不污染系统 Python
source .venv/bin/activate        # 激活（Windows PowerShell：.venv\Scripts\Activate.ps1）
pip install -r requirements-all.txt   # 装全部里程碑的依赖（fastapi、uvicorn、httpx、pytest 等）

pip 下载慢或超时：换国内镜像再装一次 pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements-all.txt

每次新开终端跑里程碑前，记得先激活环境：source .venv/bin/activate（Windows PowerShell：.venv\Scripts\Activate.ps1）。激活后命令行最前面会出现 (.venv) 字样。

只下载了单个里程碑 zip、没有全量包？也行：进入该里程碑目录后手工执行上面三条命令，把 requirements-all.txt 换成目录里的 requirements.txt。M3 / M4 / M8 / M9 只用 Python 标准库，不装任何依赖也能跑。

3. 手把手第一跑：以 M1 为例

下面是从解压到看到结果的完整过程，照着做一遍，后面 8 个里程碑都是同样的套路。

第 1 步：解压。 双击下载好的 retailhub-source.zip（macOS 会自动解出一个文件夹）。打开终端，进入目录：

cd ~/Downloads/retailhub-source    # 按你实际解压位置调整；可以把文件夹直接拖进终端窗口自动填路径
ls

预期输出看到 README.md、bootstrap.sh、m1-monolith、m2-cache-mq … m9-eval-ops。

第 2 步：建环境（首次）。 执行 bash bootstrap.sh，看到 1.3 节的四步 ✅ 输出。然后激活环境：

source .venv/bin/activate

预期：命令行提示符前面多出 (.venv)。

第 3 步：进入 M1 并启动。

cd m1-monolith
bash run.sh

run.sh 会先做种子数据初始化（生成 50 个商品、5000 张订单、30 天数据，输出类似 seed done: products=50 orders=5000），然后启动服务，最后几行长这样：

INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started server process
INFO:     Application startup complete.

看到这个说明服务已经跑起来了。这个终端窗口不要关，服务就住在里面。

第 4 步：用浏览器看接口文档。 打开浏览器访问 http://localhost:8000/docs，你会看到 FastAPI 自动生成的 Swagger 交互式接口文档页面：列出 /orders、/orders/{id}、/stats/gmv、/health 等接口，点任意一个展开，点「Try it out」→「Execute」，就能直接在网页里调接口看返回。

第 5 步：用 curl 跑验收（新开一个终端窗口）。

curl "http://localhost:8000/orders?page=1&size=5"

预期返回 JSON：含 items（5 条订单）、total（=5000）、page、size。再试：

curl http://localhost:8000/health

预期返回 {"status":"ok"}。

第 6 步：跑自动化测试。 先回到服务窗口按 Ctrl+C 停掉服务，然后：

python -m pytest tests/ -q

预期输出最后一行类似 8 passed in 0.5s，全绿即通过。

第 7 步：对照验收清单。 打开 m1-monolith/README.md 里的「验收命令对照表」，逐条 curl 验证（分页结构、详情含商品、404 为 JSON、参数校验 422、GMV 口径、访问日志……），全过后回到 卷01-2 的实战章节勾选验收清单，M1 完成，进 M2。

4. FAQ 常见问题

Q1：M6 压测全部失败，报 Server disconnected without sending a response？

你的系统代理把 localhost 请求也劫持了（macOS 上 httpx 会读系统偏好设置里的代理，本机压测走代理会被断开）。M6 的 load_test.py 已经内置了修复：创建 httpx 客户端时加 trust_env=False 参数绕开系统代理。如果你自己写 httpx 客户端遇到同样问题，照抄这个参数即可；临时验证也可以在终端里 unset http_proxy https_proxy all_proxy 后再跑。

Q2：启动时报 Address already in use（端口被占）？

说明 8000 端口已有程序在用。两个办法：① 换端口启动，如 uvicorn app.main:app --port 8001，验收命令里的 localhost:8000 同步换成 8001；② 找出占用者关掉：lsof -i :8000 查到 PID 后 kill <PID>（Windows：netstat -ano | findstr :8000）。

Q3：Windows 上 bash run.sh 跑不了？

用 Git for Windows 自带的 Git Bash 打开里程碑目录再执行 bash run.sh；或者不用脚本，在 PowerShell 里手动执行等价命令：

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.seed          # 仅 M1 需要，生成种子数据
uvicorn app.main:app --port 8000

如果 PowerShell 拦激活脚本，先执行一次 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned。

Q4：ModuleNotFoundError: No module named 'fastapi'？

没装依赖或没激活虚拟环境。回到源码包根目录执行 source .venv/bin/activate（命令行前面出现 (.venv) 才算激活成功），或全程用 .venv/bin/python 代替 python。

Q5：pip install 卡住或超时？

换国内镜像：pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements-all.txt。

Q6：想重置数据重新跑？

种子数据是确定性生成的（random.seed(42)），删掉里程碑目录里的 .db 数据库文件（如 M1 的 retailhub.db）再跑一次即可，任何人跑出的验收数字都一致。

Q7：M5 怎么没有 run.sh？

M5 是文档实战，产物是一份架构文档包（4+1 视图、质量属性场景、ADR、评审纪要），没有要运行的代码。解压后打开 m5-architecture-docs/README.md，按说明填写 docs/ 下的模板即可。

遇到问题先翻对应里程碑目录里的 README（都有「常见报错 FAQ」一节），再回到本页对照排查。
